# ADR-06: Documentación (Idioma y Herramientas)

**Fecha:** 02/08/2026
**Estado:** Aceptado

## Contexto

El proyecto tiene dos tipos de contenido: código técnico (nombres de variables, funciones, componentes) y contenido para el usuario (mensajes, textos de interfaz). Necesitamos una política clara para mantener consistencia y facilitar futuras traducciones.

## Decisión

1. **Código y desarrollo:** Todo el código (nombres de variables, funciones, componentes, mensajes de commit (solo al inicio en feat/fix/chore/refactor)) se escribe en **inglés**.
2. **Contenido para el usuario:** Todos los textos visibles para el usuario (etiquetas, mensajes de error, instrucciones, títulos) se escriben en **español**.
3. **ADRs y documentación:** Los ADRs, comentarios técnicos, documentación técnica, mensajes de commit se redactan en **español** para facilitar su comprensión por todo el equipo.
4. **Encapsulación de textos:** Todos los textos visibles en el frontend se almacenan en el directorio `src/labels/` como constantes exportables, permitiendo:
   - Centralizar cambios de texto.
   - Facilitar futuras traducciones.
   - Mantener el código limpio de strings "hardcodeados".

## Alternativas

Documentar en inglés o dejar la explicación únicamente en el código.

## Consecuencias

- ✅ Más fácil de comprender para el equipo.
- ✅ Mejor alineación con la experiencia de usuario y el contexto del proyecto.
- ⚠️ Menos portable a equipos que no compartan el idioma.
